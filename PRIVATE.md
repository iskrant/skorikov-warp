# Зашифрованные рабочие файлы

В Git хранится `private.age`. Локальные рабочие копии исключены через `.gitignore`.
Нужны Python 3 и age; SOPS не требуется для архива смешанных файлов.

На другом компьютере установите приватный age-ключ отдельно в
`~/_AI/codex-age-key.txt` с правами `600`, клонируйте проект и запустите:

```sh
./scripts/codex
```

Команда восстанавливает документы и skills до запуска Codex, устанавливает
pre-commit hook, затем запускает `$CODEX_LAUNCHER`, если он задан, иначе
исполняемый `~/codex.sh`, иначе `codex` из PATH. Аргументы передаются без изменений.
`SOPS_AGE_KEY_FILE` устанавливается в путь `AGE_IDENTITY` или стандартный путь ключа.

Для обычного запуска Codex настроен `.codex/hooks.json`: `SessionStart` выполняет
подготовку на startup/resume. Один раз доверьтесь проекту и точному определению
hook через `/hooks`; без этого Codex пропустит hook. Файл hook оставлен открытым,
чтобы его можно было обнаружить до расшифровки. Если инструкции восстановлены
после первоначального обнаружения, hook просит агента прочитать их явно.

Подготовка вручную (в том числе перед работой в IDE):

```sh
python3 scripts/private.py prepare --install-hooks
```

Повторная подготовка сохраняет локальные изменения. После `git pull` она
обновляет неизменённые файлы и пытается объединить независимые изменения.
Если нет ключа или есть конфликт, возвращает ошибку вместо перезаписи.

После изменения служебных документов или ключей:

```sh
python3 scripts/private.py seal
git add private.age
python3 scripts/private.py check --staged
```

`seal` шифрует служебные документы, локальные конфиги, `.agents/`, `.codex/`,
все `AGENTS.md`/`SKILL.md` вне генерируемых каталогов и содержимое `.private/`.
Единственное публичное исключение в `.codex/` — startup hook `hooks.json`.
Новые пароли и ключи размещайте в `.private/`; этот каталог не используется Hugo.
Файлы сайта, публичные инструкции и workflows остаются открытыми для сборки.

Команда `unseal` по-прежнему отказывается перезаписывать отличающиеся файлы.
`prepare` и `merge` используют зашифрованную базовую версию в локальном Git-каталоге
`private-vault/base.age`. Ничего не устанавливается в `~/.ssh` или `/etc`.
Ключи доступны в `.private/keys/`, созданные файлы имеют права `600`.

## Проверка commit

Подготовка устанавливает `core.hooksPath=.githooks` только в этом клоне. Чужие
hooks не заменяются: при их наличии нужно вручную подключить вызов
`python3 scripts/private.py check --staged` к существующему pre-commit.

Hook блокирует commit, если рабочие файлы отличаются от архива, свежий архив
не добавлен в индекс или защищённый plaintext попал в индекс. Без age-ключа
проверка тоже блокирует commit. Hook не шифрует и не добавляет файлы сам.
Обычный `check` проверяет рабочую копию; `check --staged` проверяет ещё и индекс.
Изменения игнорируемых файлов не видны в `git status`. Не используйте `git add -f`
или `--no-verify` для обхода проверки. В новом клоне hooks устанавливаются заново.

## Merge

```sh
python3 scripts/private.py merge
python3 scripts/private.py seal
git add private.age
```

Трёхстороннее слияние: базовая версия, локальные файлы, входящий архив. Независимые
правки UTF-8 документов объединяются через `git merge-file`. Односторонняя замена
ключа допустима; при изменении ключа с двух сторон автоматического слияния нет.
Содержимое `.private/` никогда не объединяется построчно. Удаление против правки
также является конфликтом. При конфликте рабочие файлы, архив и база не меняются;
в сообщении только имена файлов. Можно локально привести конфликтующий файл
к выбранной входящей версии и повторить merge, затем внести итоговые правки.

Перед применением изменений сохраняется зашифрованный снимок рабочих файлов в
Git-каталоге `private-vault/backups/`. Восстановление из него выполняется вручную
в отдельный закрытый каталог; содержимое не выводить в терминал/чат.
Операции записи vault сериализованы локальной блокировкой. В случае сбоя файловой
системы во время применения merge сохранённый снимок позволяет восстановиться.

Для бинарного конфликта `private.age` в самом Git, когда локальные plaintext-файлы
соответствуют нашей стороне:

```sh
python3 scripts/private.py merge --base-ref <общий-коммит> --theirs-ref <входящий-коммит>
python3 scripts/private.py seal
git add private.age
```

Без базовой версии автоматический merge не выполняется. При намеренном удалении
приватного файла используйте `seal --allow-delete`; обычный `seal` защищает от
случайной упаковки неполного рабочего каталога. Неизменённый архив не шифруется
заново, чтобы не создавать лишний бинарный diff.

Skill: `.agents/skills/private-vault/SKILL.md`, доступен после подготовки.
Он описывает age-хранилище и работу с отдельными SOPS-файлами. `private.age`
не является SOPS-файлом; формат хранения не меняется.

Приватный age-ключ никогда не входит в архив: переносите его отдельно.
Публиковать на сайт следует только `public/`, не корень репозитория.
Шифрование не удаляет открытые версии из старых коммитов; ранее раскрытые
учётные данные требуют замены. Хранилище не скрывает публичную историю проекта.
